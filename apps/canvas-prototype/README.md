# Canvas prototype — layer-model validation

A vanilla-JS canvas app wrapping the proven E2/E3 loop (depth-locked render +
host ground-truth instance masks + FLUX.2 [pro] Edit material swap) in
direct-manipulation UI: hover a region, click to select, pick a swatch, get a
non-destructive material **layer**.

## Run

```
spike\.venv\Scripts\python.exe apps/canvas-prototype/prepare_data.py   # once (idempotent)
spike\.venv\Scripts\python.exe apps/canvas-prototype/server.py
# open http://localhost:8765
```

## What works

- **Hover** any region → tinted highlight (color = semantic) + tooltip with
  semantic and CSI layer path.
- **Click** selects (shift/ctrl-click adds); single-semantic selections get a
  "Select all \<semantic\>" button.
- **Apply**: select region(s) + a swatch → POST `/api/apply_material` →
  result arrives as a layer (RGBA: edit pixels inside the instance mask,
  transparent outside).
- **Layer stack** (left panel): eye-toggle and delete recomposite client-side
  instantly from cached layer images (no network). Re-applying a different
  material to the *same* selection **replaces** that selection's layer
  (master-plan criterion #4/#5).
- **Persistence**: layer state in `localStorage`; layer images cached under
  `public/project/layers/<hash>.png` — the project reopens with layers intact.

## Mocked vs live

- **No-spend demo path**: `travertine` on `wall` regions serves the
  precomputed E3 result (`spike/outputs/e3_swatch/final_composite.png`)
  masked to the requested instances — zero API calls.
- **Live path** (everything else): FLUX.2 [pro] Edit via fal.ai
  (`fal-ai/flux-2-pro/edit`, `[render JPEG, swatch JPEG]` data URIs, the exact
  `spike/run_e3_swatch.py` recipe), then `spike/composite.paste_tile` with the
  union instance mask (2px dilation). ~$0.06 and ~60–90 s per call.
  Requires `FAL_KEY` in `spike/.env`. **Budget guard:** server refuses after
  8 live calls per session (~$0.50); each call's est. cost is logged to stdout.
- Identical (swatch, region-set) requests are served from the layer cache.
- Swatches: `travertine.jpeg` is the real E3 asset; the other four
  (red brick, charcoal seam, white stucco, weathered cedar) are **procedural
  PIL placeholders** generated by `prepare_data.py`.

## Data contract (`public/project/`, generated from `spike/outputs/e2_house/`)

- `base.png` — the E2 `flux_depth` render, 1504×656 (pixel-registered to the
  host ground truth).
- `ids_rgb.png` — per-pixel instance ids packed losslessly for HTML-canvas
  readback: `r = id & 255`, `g = (id >> 8) & 255`, `b = 0`; source
  `instance_ids.png` (1514×659 uint16) NEAREST-resized to base size. Verified
  to roundtrip exactly.
- `regions.json` — `{size, regions: {id: {semantic, layer, name, guid}},
  semantics: {semantic: {label, color}}}`. Instance id *i* maps to the
  (i−1)-th key of `objects.json`'s `objects` dict (same mapping as
  `spike/host_probe_rhino.py:mask_for`). 251 of 326 table objects appear in
  frame.
- `swatches/` — material thumbnails (also used as FLUX.2 Edit reference
  images on the live path).

## API

`POST /api/apply_material`
body: `{"region_ids": [2, 17], "swatch": "travertine"}` or
`{"region_semantic": "wall", "swatch": "red_brick"}`
→ `{"layer_id", "image_url", "cost_est", "live", "cached"}`
