## What was done
Created two files:

1. `spike/tests/fixtures/tag_regions_response.json` — a hand-authored fixture with nine regions covering most of the `Region.LABELS` vocabulary (sky, ground, wall, roof, window x2, door, mullion, vegetation). The mullion is a child of a window which is a child of the wall — exercises the `parent_id` chain. Coordinates target the 1024x1024 spike2 render so the dry-run produces a visually meaningful overlay on `spike/outputs/spike2/render.png`.

2. `spike/test_vlm_tagging.py` — argparse driver with three modes of operation:
   - `--dry-run` (default when no mode flag is set) — loads the fixture JSON, validates it through `TagRegionsResponse.model_validate(...)`, never touches the network.
   - `--live` — `import modal` inside `_call_live(...)` (kept out of module top so `import spike.test_vlm_tagging` works without modal CLI auth), then `modal.Function.lookup("arch-rendering-spike", "tag_regions").remote(screenshot_bytes, render_bytes)`. Requires `--screenshot` in addition to `--input`. Handles three return shapes the Modal function might serialize as: a `TagRegionsResponse` instance, a JSON string/bytes, or a plain dict.
   - In either mode, draws labeled translucent rectangles on the render with PIL (`ImageDraw.rectangle` + `Image.alpha_composite`) plus a small black label strip with `id:label conf` for each region. Color is keyed by label so eyeballing is easy. Falls back from `arial.ttf` to `ImageFont.load_default()` on systems without arial.

The output filename is derived from the input stem (`tagged_<stem>.png`) so multiple input renders don't clobber each other.

## Surprises / notes for the human
- The dry-run produced an output PNG at `spike/outputs/spike3/tagged_render.png` as a side effect of testing. I did NOT stage it because the task's `Files:` column only lists the driver and the fixture, and the T17 spec explicitly owns `spike/outputs/spike3/`. The file is on disk for you to eyeball, but it's not in git.
- The `import modal` is intentionally inside `_call_live(...)`, mirroring the pattern in `spike/renderers/nano_banana.py`. Module import works fine without modal CLI auth — important so the file can be imported by future pytest tests that monkeypatch `_call_live`.
- The fixture's coordinates assume a roughly 1024px-wide render. On a smaller render some boxes will be clipped past the right/bottom edges. PIL silently clips, so the visualization still works — it just looks cropped. The schema validators don't complain because we only require `x,y >= 0` and `w,h > 0`.
- I sanity-checked that the fixture's `parent_id` references are valid (`r8` → `r5` → `r3`), but the schema does not enforce referential integrity (per T13 follow-up). A `--strict` flag could add that later if needed.
