# E1 — Rhino native-extraction probe (keystone)

- **Task:** Prove a Rhino plugin can export pixel-accurate per-object ID masks + true depth + an object/material table, eliminating the VLM-tag + SAM2 stages on the plugin tier.
- **Status:** **GATE PASSED.** 93.1% of object pixels decode exactly to their source object; 257 individual mullion instances carry pixel-accurate masks at 2–4px width; true z-buffer depth captured.
- **Cost:** $0 (all local, via the Rhino MCP bridge — no plugin install needed).
- **Date:** 2026-06-12
- **Test model:** `SFUrban Rhino model for claude.3dm` (user's real studio project; 5,134 objects, incl. layers `ENSCAPE::GLASS::MULLIONSS` (543 mullions), `ENSCAPE::EXTERIOR WALL::CONCRETE PANELS` (137), `ENSCAPE::GLASS` (118), doors, pergola, site context).

## The three findings that matter (hard-won, save future re-derivation)

1. **Rhino's "unlit" isn't unlit — but it's exactly linear.** A custom display mode (copy of Shaded; `LightingScheme=None`, edges/curves/shadows off, `DisableTransparency=True`) still applies a camera headlight: `out_ch = 0.7·in_ch + base_ch(pixel)`. The 0.7 slope is constant across the whole frame; the additive base varies per pixel/channel with surface orientation. Single-pass exact-color decoding is impossible…
2. **…so capture a white reference pass.** With every object pure white, `white_ch = 0.7·255 + base_ch`, giving the per-pixel/per-channel base. Decode becomes exact and self-calibrating: `in_ch = (id_ch − (white_ch − 178.5)) / 0.7`. This two-pass scheme took decode from **0% → 93.1%**. ID colors use r=0 as a marker channel and a g/b grid of 5 (max ~2,700 objects/frame; widen grid or add r-levels for more).
3. **Captures must be atomic.** The hidden Rhino viewport resized between separate MCP calls (902→659px height), silently breaking pass alignment. One script = one camera = aligned passes. Also: disable grid/axes (`vp.ConstructionGridVisible/ConstructionAxesVisible/WorldAxesVisible`), and set `vp.DisplayMode = mode` rather than passing the mode to `CaptureToBitmap` (which ignored updated attributes).

## Gate evidence

- **Mullions:** ground-floor glazing decodes as alternating glass/mullion vertical strips, each 2–4px wide, *each a separate instance with its own GUID*. T21's measured Gemini result on equivalent content was **zero mullions detected on an entire mullion-grid facade**. The plugin tier doesn't improve on the VLM — it replaces it with ground truth.
- **Unmatched 6.9%** of object pixels are anti-aliased edge pixels that fail the residual check — they stay *unassigned* rather than misassigned. Mitigations if needed: capture at 2× and downsample nearest-neighbor, or nearest-instance fill.
- **Depth:** true z-buffer at viewport resolution; values are perspective-divided and scaled per capture (per ZBufferCapture docs) — normalize before ControlNet use (E2). Ground plane has no geometry in this model, so depth covers buildings only.

## Caveats / follow-ups

- **Semantics = layer discipline.** The big tower masses live on layer `3D` → semantic "other" (86k px). Exactly as predicted by the research: Rhino semantic quality depends on the architect's layer naming. The objects.json `name`/`layer` fields + a cheap VLM pass over the object *list* (not pixels) is the planned fix; Revit's native categories avoid this entirely.
- Depth resolution is viewport-capped; for 4K, resize viewport programmatically (flicker) or accept beauty/depth at different scales.
- `open_doc`'s `clearFirst` crashed twice (`NullReferenceException`) on non-empty docs; `doc.Import()` via `run_python` after a fresh slot is reliable.
- The leftover `E1_IDMask` display mode persists in the Rhino install — harmless, reused on next run.

## Verdict

The keystone hypothesis is validated on a real project model: a ~150-line Rhino-side script (no compiled plugin, no conduit needed) yields ground-truth instance masks + semantics + true depth + camera. Tag+segment stage deletion on the plugin tier is real. Proceed to E6 (feed `mask_for(semantic=='wall')` into the composite path) and E2 (depth-conditioned rendering with `depth.png`).
