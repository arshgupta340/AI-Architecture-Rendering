## What was done

Wrote `spike/tests/test_end_to_end.py` -- eight pytest cases that cover the T19 driver from both ends:

Four unit-style tests pin down `_pick_region` behavior in isolation: highest-confidence match wins, ties break deterministically by region id, an unmatched-but-valid label raises `RuntimeError`, and an out-of-vocabulary label raises `ValueError`. These are the rules the driver relies on; they earn dedicated cases because a regression here would silently re-route edits to the wrong region.

Four integration-style tests run `end_to_end_edit.main([...])` against a fully mocked Modal world:

1. `test_end_to_end_pipeline_mocked` -- the headline test. Stubs each of the four Modal functions via a fake `modal` module injected into `sys.modules`. Verifies (a) `modal.Function.lookup` is invoked with the right app + function name; (b) every stage runs exactly once; (c) the call order is exactly `render -> tag -> segment -> apply_material`; (d) the bbox passed to `segment` matches the highest-confidence wall (r2, not r1); (e) the material_name argument is derived from the file stem with underscores -> spaces; (f) the final composite is non-empty bytes that decode as a real 32x32 PNG.
2. `test_end_to_end_picks_window_not_wall` -- swaps `--region-label` to `window` and confirms `segment` receives a different bbox. Catches "selector is hardwired" regressions cheaply.
3. `test_end_to_end_dry_run_makes_no_modal_calls` -- default `--dry-run` path must never touch modal. We wire `modal.Function.lookup` to an `AssertionError` and verify it is never called, plus that the printed call graph contains "DRY RUN" and the cost line.
4. `test_end_to_end_unknown_label_short_circuits` -- supplying an out-of-vocab label in `--live` mode raises `ValueError` *before* any Modal lookup, protecting the architect from spending $0.50 on a typo.

The cache is redirected to a `tmp_path`-scoped directory via an `isolated_cache` fixture that monkeypatches `spike.cache._CACHE_ROOT`. That keeps the test hermetic -- it can be run from a clean checkout and never touches `spike/.cache/`.

The composite step is genuinely exercised (PIL is not mocked), so the assertion that the output is a real PNG with the expected base resolution catches real PIL-side regressions in `composite.paste_tile`.

## Surprises / notes for the human

- The driver's stages each pass a `materialize_to_bytes` function into `cache.get_or_compute`. That function returns either bytes or a Pydantic model (for `tag_regions`, where the result gets JSON-serialized before caching). The driver already handles both. The test passes `TagRegionsResponse` directly back from the mocked Modal stub, which exercises the in-driver "isinstance(result, TagRegionsResponse) -> model_dump_json().encode()" branch. If that branch ever silently breaks, this test will fail.
- I considered also asserting that the disk cache was *written* (i.e., `cache_path(...).exists()` after the run). I left it out: it would couple the test to the cache layout, and a future refactor of `cache.py` keys would needlessly break it. The cache layer has its own contract tests covered by T18.
- The "material_name = file.stem.replace('_', ' ')" assertion is a real coupling between the driver and the test. If the driver's stem->name conversion changes, both need to update. The test name and inline comment flag this clearly.
- I avoided introducing any new fixture into `conftest.py`. The fake-render/fake-mask/fake-tile/fake-tag fixtures are scoped to this test file because they encode T20-specific assumptions (e.g., 32x32 base size, the four-region tag layout). Putting them in `conftest.py` would tempt future tests to reuse them and accidentally inherit those assumptions.
