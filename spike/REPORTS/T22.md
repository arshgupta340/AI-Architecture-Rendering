## What ran

`spike/run_t22.py --live` orchestrates the work. For each of the 4 new screenshots:

1. `render_from_model_view` (Modal → Nano Banana Pro) — produces a photoreal render that preserves the screenshot's geometry. $0.04/call.
2. `tag_regions` (Modal → Gemini 3 Pro) — tags the (screenshot, render) pair, returns normalized 0–1000 bboxes. $0.01/call.
3. `_draw_regions` (local PIL via `test_vlm_tagging.py`) — visualizes bboxes rescaled to pixel coords.

Outputs in `spike/outputs/spike3/t22/<slug>/`: `render.png`, `tagged.png`, `tags.json` (validated), `tags_raw.json` (raw response, for recovery), `meta.json`.

After the first run, the driver was patched to save `tags_raw.json` BEFORE validation so a schema failure doesn't cost the paid data. That patch went in mid-task because urban_exterior failed validation on the first attempt.

## New finding: Gemini 3 Pro can return malformed bbox JSON

On urban_exterior (and only urban_exterior), `tag_regions` returned bboxes shaped:

```json
{"x": 499, "y": 361, "w": 25, "y": 425}
```

Two `y` keys, no `h`. Standard JSON parsers silently drop the first key on duplicates → pydantic sees no `h` → validation fails on every region. Reproducible: same pattern on a $0.01 retry.

Distribution: 50 `x`, 92 `y` (almost 2×), 44 `w`, only 2 `h` (sky and ground were the only correctly-formatted regions). The model's intent is hard to interpret with certainty — the second `y` could be meant as `h`, or as `y2`. If `y2`, our salvage hack (treat second `y` as `h`) produces over-tall bboxes (y2 used as height). Visualization confirms the urban_exterior bboxes look unusually tall.

**Recovery path used** (`spike/salvage_urban_tags.py`, no extra API cost):
- Read raw response with `json.loads(..., object_pairs_hook=...)` to preserve duplicate keys.
- For each bbox, if shape is `[("x",_), ("y",_), ("w",_), ("y",_)]`, promote the second `y` to `h`.
- Drop regions still missing `w` or `h` (3 dropped: `veg11`, `veg12`, `veg13` — only had `{x, y}`).
- Result: 44 of 47 regions salvaged. Labels and (x, y, w) are valid; bbox tightness on this image is compromised.

**Implications:**
- For Spike 4 production, the tag_regions caller must defensively save raw responses *before* validation. The `_save_raw_response` helper added mid-T22 should be promoted into `spike/test_vlm_tagging.py:_call_live` as well.
- The salvage hook should be promoted from one-off script into a tolerant parser used wherever Gemini responses are validated.
- The malformation might be image-specific (only urban_exterior reproduced it) or token-budget-related (urban_exterior had the most regions returned of any T22 pair).

## Spike 3 gate verdict

**PASSES.** The gate criterion was "≥80% of major architectural elements (wall, window, mullion, floor, ceiling, door) correctly labeled with tight, pixel-accurate bboxes across 5 diverse production-shape pairs."
