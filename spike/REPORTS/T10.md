## Surprises / notes for the human

- `FAL_KEY` is listed in the env example but **no renderer currently consumes it.** The task row explicitly named it as a placeholder for the bake-off plan; I documented this as "reserved" in both files so future-you doesn't go hunting for a missing `fal_*.py` client.
- The native `RecraftV3Renderer` (in `recraft.py`) and the Replicate-hosted `RecraftV3ReplicateRenderer` (in `replicate_models.py`) hit the same underlying model through different infrastructure. Both are kept in the bake-off intentionally. PROVIDERS.md calls this out so the comparison grid isn't read as redundant.
- Prices were taken from each renderer class's `cost_per_call_usd` ClassVar. If those values are stale, fix them in code and re-sync the docs.
- Magnific API access is invite-gated as of this writing; the architect may need to fall back to Freepik's API surface (same model, different endpoint) before a live call works. I did not document the Freepik endpoint shape — that's a follow-up task if Magnific blocks us.
