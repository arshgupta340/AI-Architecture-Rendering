## What was done
Added a new `tag_regions(screenshot_bytes, render_bytes, ...)` function to `spike/modal_app.py`, decorated with `@app.function(secrets=[secret], timeout=120)` — same wiring as the existing `generate` / `render_from_model_view` functions. It calls Gemini 3 Pro (`gemini-3-pro-preview`) via the existing `google.genai` client pattern. The two images are passed as `types.Part.from_bytes(...)` plus an instruction string that:

1. Tells the model the bbox coordinate space is the **render** (image 2), not the screenshot — important because downstream SAM2 and inpainting all operate on the render.
2. Lists the allowed labels by iterating `Region.LABELS` from `spike/schemas.py` (single source of truth).
3. Describes the JSON shape per region (id, label, bbox{x,y,w,h}, confidence, optional parent_id).

Structured output is enforced via `GenerateContentConfig(response_mime_type="application/json", response_schema=TagRegionsResponse)`. The function returns the parsed pydantic object directly via `response.parsed` when available, with a `model_validate_json(response.text)` fallback for SDK versions that don't auto-populate `.parsed`.

The function is not deployed — `modal run` is intentionally not invoked. T17 (the live smoke test) is the first place this will hit the network.

## Surprises / notes for the human
- The `from spike.schemas import …` import is **inside** the function body, not at module top. Rationale: `modal_app.py` is run both as a script (via `modal run`) and as an import target (e.g., the new `NanoBananaProRenderer` in `spike/renderers/nano_banana.py` does `Function.lookup("arch-rendering-spike", "render_from_model_view")`). Module-top `from spike.schemas import` would break script-mode invocation where `spike` is not a package on `sys.path`. Inside the function it runs in the Modal container, where `spike` will need to be available — see follow-up.
- `response_schema=TagRegionsResponse` passes the pydantic class directly. The current `google-genai` SDK (2.4.0 in our venv) converts pydantic v2 models to OpenAPI schema. The `Region.LABELS` ClassVar is not part of `model_dump()` (verified in T13), so it does not leak into the schema; the label vocabulary is communicated via the *instruction prompt* and re-enforced by the pydantic field validator at parse time. This is belt-and-suspenders: the model is *told* the allowed labels and the parser *rejects* anything else.
- I did not add `tag_regions` to the `local_entrypoint()` `main()` — the spec says don't deploy, and `main()` is the live demo path. T16 will provide the local driver.
