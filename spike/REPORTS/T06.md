## What was done
Wrote `spike/renderers/replicate_models.py` with three `Renderer` subclasses (`QwenImageEditRenderer`, `HiDreamE1Renderer`, `RecraftV3ReplicateRenderer`) sharing a `_ReplicateRendererBase` for the standard Replicate submit-then-poll HTTP flow. The base reads `REPLICATE_API_TOKEN` at call time (not import time), encodes the screenshot as a `data:image/png;base64,...` data URL so no upload is needed, POSTs to either `/v1/models/<owner>/<name>/predictions` (default-version path) or `/v1/predictions` with a pinned `version` hash if a subclass sets `model_version`, polls `urls.get` on a 2 s cadence until `succeeded`, then GETs the first `output` URL and returns the raw bytes. `requests` is imported lazily inside `render()` to keep module load cheap and consistent with the other provider modules.

## Surprises / notes for the human
- Recraft V3 on Replicate is fundamentally a text-to-image model; sending the screenshot via the `image` input only acts as a style reference (and may be ignored entirely depending on Replicate's input schema for `recraft-ai/recraft-v3`). For an apples-to-apples bake-off with the other renderers (which are all image-conditioned), prefer the native `RecraftV3Renderer` in `recraft.py`. The Replicate variant is included to score "what if we only had Replicate as a provider" but expect lower silhouette IoU.
- `model_version` is `None` for all three classes — they will hit Replicate's "default version" endpoint, which is what the public Replicate console uses. If the bake-off needs deterministic version pinning, set `model_version: ClassVar[str]` on each class to the SHA shown on the model's "API" tab. I left it unset because the model version hashes change frequently and pinning them now would just be guessing.
- The `data:` URL encoding adds ~33% overhead over a binary upload. For a 1920px screenshot at ~2 MB that's a ~2.7 MB JSON body — Replicate accepts this fine (their docs explicitly recommend it for one-shot calls), but if a future task needs to batch many calls, switch to pre-uploading via `https://api.replicate.com/v1/files` and passing the returned URL.
- T11 will need `respx` mocks for these endpoints. The relevant request shapes to mock are: `POST {base}/models/<owner>/<name>/predictions` → `{"id":"...", "urls":{"get":"..."}, "status":"starting"}`, then `GET <get-url>` → `{"status":"succeeded", "output":["https://..."]}`, then `GET <output-url>` → image bytes.
