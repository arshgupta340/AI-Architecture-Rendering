## What was done

Updated the `segment()` Modal function signature from `(image_bytes, click_x, click_y)` to `(image_bytes, click_x=None, click_y=None, prompt=None)`. The new preferred call shape is `prompt={"type": "point", "x": ..., "y": ...}` or `prompt={"type": "bbox", "x": ..., "y": ..., "w": ..., "h": ...}`. The bbox path maps directly to SAM2's `predictor.predict(box=[x1, y1, x2, y2])` API, while the point path keeps the existing `point_coords` / `point_labels` flow. A deprecation shim normalizes the legacy positional `(click_x, click_y)` form into a point prompt and emits `DeprecationWarning`. Mutually-exclusive validation rejects callers that pass both shapes simultaneously, and the bbox path clips to image bounds and raises on zero-area boxes.

The existing local entrypoint `main()` calls `segment.remote(base_bytes, click_x, click_y)` — that legacy positional call shape continues to work via the shim, so no other call sites needed changes.

This change had actually been left uncommitted on disk from a prior session (the working tree already contained the implementation). T15 simply commits it.

## Surprises / notes for the human

- The bbox path uses `box=np.array([x1, y1, x2, y2])` with no point prompts. SAM2 accepts box-only prompts and returns its three candidate masks per usual; `multimask_output=True` is preserved so the best-IoU mask is selected the same way as before.
- Clipping logic: x2/y2 are clipped against `w-1`/`h-1` (same convention used for the point path). If a VLM bbox extends to the image edge, this still yields a usable >1px box. A zero-area result raises a clear error.
- The deprecation shim warns at `stacklevel=2` so callers see the warning at their own call site, not inside `modal_app.py`.
