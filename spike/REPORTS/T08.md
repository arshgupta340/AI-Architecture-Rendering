## What was done
Wrote `spike/compare_renderers.py`, the B3 bake-off driver. The script imports every renderer class from `spike/renderers/` (Nano Banana, two FLUX variants, Magnific Mystic, native Recraft, and three Replicate-hosted models), inspects `os.environ` for each one's `env_var`, and instantiates only the live ones. For each live renderer it calls `.render(screenshot, prompt, seed=...)` inside a try/except, writes the returned PNG bytes to `spike/outputs/spike2_5/b3/<name>.png`, and accumulates rows for a `scores.csv` rubric template. After the run it assembles `comparison_grid.png` (raw renders side by side) and `overlays_grid.png` (each render with the source's Canny edges overlaid in red) by reusing `extract_edges`, `make_overlay`, `label_image`, and `build_grid` from `run_b1_baseline.py` — same visual style as B1.

Dry-run default: with zero provider env vars set, the driver prints a manifest table showing every renderer with `[LIVE]` or `[skip]`, then exits 0 without creating any files. This is the path the architect will exercise locally tomorrow before adding keys, and it is verified below.

The `scores.csv` columns mirror B1's `scoring_rubric.json` vocabulary (critical/high/medium/low failure counts, 1-10 subjective scores on photorealism / material / lighting) plus the two CV metrics from T07 (`silhouette_iou`, `edge_density_delta`) as empty columns the architect fills after eyeballing the grids. The driver does not currently compute the CV metrics itself — that's an intentional follow-up so the architect can review which renders failed before paying the CPU cost on a grid of 8 renders.

## Surprises / notes for the human
- Path bootstrap: when the script is invoked as `python spike/compare_renderers.py` from the repo root, `spike/` isn't on `sys.path`, so `import run_b1_baseline` would fail. I prepend both `spike/` and the repo root to `sys.path` at module top so the script runs the same way `run_b1_baseline.py` does (also a top-level script in `spike/`). The lint-style `# noqa: E402` markers on the post-bootstrap imports are intentional.
- The grid builder takes `cols=len(panels)` so every grid is one tall row including the SOURCE panel. With 8 live renderers + source that's 9 cells wide — fine on a wide monitor, painful on a laptop. If the architect wants a 3x3 layout, `build_grid` already takes a `cols` arg but doesn't actually wrap rows in the B1 implementation; that's a follow-up if the visual gets unwieldy.
- CV-metric columns (`silhouette_iou`, `edge_density_delta`) are left empty in the CSV. The T07 scoring functions are available — wiring them in is a one-line addition per row — but I left them blank because (a) the rubric is for the architect's eye first and (b) computing IoU on 8 renders pre-review wastes ~1s of CPU for noise. If you want them auto-populated, add a `score_with_cv(source_bytes, render_bytes)` call after the `render_bytes = r.render(...)` line.
- Replicate's `RecraftV3ReplicateRenderer` shares the `REPLICATE_API_TOKEN` env var with the Qwen and HiDream renderers, so setting that one key turns on three rows at once. That's intentional — Replicate is one provider — but worth flagging if the spend budget needs per-model control.
- The driver catches every exception per-renderer and continues, so one provider going down doesn't abort the whole bake-off. The CSV gets `status=error` and `notes=<repr(exception)>` for that row, and the failing renderer is excluded from the grids.
