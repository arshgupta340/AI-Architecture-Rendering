## What was done

Created two pure-local helper modules used by the T19 end-to-end edit driver.

`spike/cache.py` implements a tiny disk-backed cache. `get_or_compute(key, fn, scope)` reads `spike/.cache/<scope>/<key>.bin` if present, otherwise calls `fn()`, writes the result atomically (tmp → rename), and returns it. Keys and scopes are sanitized to a conservative filename charset (`[A-Za-z0-9._-]`) so the same code works on Windows and POSIX. fn() is required to return bytes; anything else raises TypeError immediately so pipeline type bugs surface loudly. A `cache_path(key, scope)` helper is exported for tests/debugging.

`spike/composite.py` implements `paste_tile(base, mask, tile) -> bytes`. It mirrors the existing `modal_app.composite()` idiom: open base as RGBA, resize tile and mask to base.size, then `Image.composite(tile, base, mask)`. The mask is opened as L, so non-binary masks blend smoothly (free soft edges from SAM2 if available). Output is PNG-encoded RGB bytes.

- The `modal_app.composite()` argument order is `(base, tile, mask)` but T18 spec calls for `paste_tile(base, mask, tile)`. I followed the task spec; T19 callers should use the new ordering. The internal `Image.composite(tile, base, mask)` PIL call is unchanged, only the wrapper signature differs.
- Cache root is `spike/.cache/`, sibling to `.venv/`. Add it to `.gitignore` if not already ignored — the spike code never commits cached blobs, but `git add .` would pick them up. I did not modify `.gitignore` because it was outside the task's `Files` column.
- Atomic write uses `Path.replace()` which is atomic on POSIX and best-effort on Windows; good enough for a single-writer dev cache.
