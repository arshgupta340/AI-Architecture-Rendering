- **Task:** T22 only avoided losing $0.01 of paid data because we wrote `_save_raw_response` and `salvage_urban_tags.py` ad-hoc mid-run. Move both into `spike/schemas.py` (one canonical helper + one alternate constructor), then have `test_vlm_tagging.py:_call_live` and `end_to_end_edit.py:_run_tag_regions` use them so every production path is defended against Gemini's known output bugs.
- **Status:** Complete. 16 new pytest tests added; full suite 50/50 green; salvage script confirmed behavior-preserving on the urban_exterior raw response (44 salvaged + 3 dropped, identical to T22 result).
- **Cost:** $0.00. No API calls.
- **Date:** 2026-05-20

## Why T23 exists

T22 surfaced a categorical Gemini-side bug: on certain images it returns bboxes with duplicate `y` keys and no `h`. JSON parsers drop the first duplicate key, so pydantic sees `{x, y, w}` and rejects every region. T22 burned $0.01 confirming reproducibility on the retry, then wrote a one-off salvage to recover the 44 of 47 regions from the raw response. That salvage logic — plus the "save raw before validation" discipline — only existed in `spike/run_t22.py` and `spike/salvage_urban_tags.py`. Spike 4 production paths (`test_vlm_tagging.py`, `end_to_end_edit.py`) still had the brittle path that lost data on schema failure. T23 fixes that.

## Changes

### 1. `spike/schemas.py` — canonical helpers

- **`save_raw_response(out_dir, raw, *, filename="tags_raw.json") -> Path`** — persists a Gemini response to disk before validation. Handles `str`, `bytes`, and arbitrary JSON-serializable objects. Creates the directory if missing. Returns the path written.
- **`_bbox_pairs_hook(pairs) -> dict`** — module-level JSON `object_pairs_hook` that promotes a duplicate `y` to `h` for bbox dicts shaped `[("x", _), ("y", _), ("w", _), ("y", _)]`. No-op for any other key sequence (region dicts, top-level dicts, well-formed bboxes).
- **`TagRegionsResponse.parse_tolerant(raw) -> TagRegionsResponse`** — alternate constructor that tolerates:
  - existing `TagRegionsResponse` instance (returned as-is),
  - `dict` with `regions` key (validated directly),
  - bare `list` of region dicts (wrapped in `{"regions": ...}`),
  - `str`/`bytes` JSON of either,
  - Gemini's duplicate-`y` malformation (repaired via the pairs hook during JSON decode),
  - regions whose bbox is still missing `w` or `h` after repair (dropped from the response; the list of dropped region IDs is stashed on the instance as `__dict__["_dropped_region_ids"]` so the caller can log or surface it).

  Label-vocabulary validation is NOT relaxed — invalid labels still raise, because letting bad labels through would silently degrade downstream segmentation.

### 2. `spike/test_vlm_tagging.py:_call_live` — use the helpers

```python
def _call_live(screenshot_bytes, render_bytes, *, raw_save_dir=None):
    fn = modal.Function.from_name("arch-rendering-spike", "tag_regions")
    result = fn.remote(screenshot_bytes, render_bytes)
    if raw_save_dir is not None:
        save_raw_response(raw_save_dir, result)
    return TagRegionsResponse.parse_tolerant(result)
```

The script's `main()` now passes `raw_save_dir=args.output_dir` when in `--live` mode, and prints any dropped region IDs so the operator sees the salvage transparently.

### 3. `spike/end_to_end_edit.py:_run_tag_regions` — use the helpers

Same shape: optional `raw_save_dir` arg. The cache layer still stores canonical post-tolerant-parse JSON, so cached calls are unchanged. On a cache miss, the raw response is saved (when `raw_save_dir` is given) before any validation, then `parse_tolerant` runs. The live runner (`_run_live`) passes `raw_save_dir=output_path.parent` so the salvageable raw lands next to the final composite output, and prints dropped region IDs.

### 4. `spike/run_t22.py` + `spike/salvage_urban_tags.py` — consolidation

Both scripts had ad-hoc copies of `_save_raw_response` and the JSON-repair hook. T23 deletes both copies and routes them through `spike/schemas.py`. Net code reduction; single source of truth for the parser; future malformed-response bugs are fixed in one place.

### 5. `spike/tests/test_schemas.py` — coverage

16 new tests across three groups:

- `save_raw_response` (4 tests) — str/bytes/object serialization + directory auto-creation.
- `_bbox_pairs_hook` (3 tests) — repairs the duplicate-`y` pattern; leaves clean bboxes alone; leaves non-bbox dicts alone.
- `TagRegionsResponse.parse_tolerant` (9 tests) — instance pass-through, dict with regions key, bare list dict, JSON str (regions-key + bare-list), bytes input, duplicate-`y` recovery using the **exact byte sequence Gemini produced on urban_exterior**, drop-unrecoverable-but-keep-response, mixed clean/malformed regions, empty `_dropped_region_ids` on clean input, invalid-label rejection.

The duplicate-`y` regression test uses a literal JSON string with two `y` keys (json.dumps can't produce that, so the test hand-constructs it) — guarantees any future refactor that breaks duplicate-key handling fails CI.
