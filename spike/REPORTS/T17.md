## Blockers

### Blocker 1: `tag_regions` Modal function is not deployed

The smoke test relies on `modal.Function.lookup("arch-rendering-spike",
"tag_regions").remote(...)` — i.e. it fans out from the local machine to a
remote function already running on Modal. Probing the app's deployed
functions shows:

```
generate:               deployed (fu-FZC3y9wPiLYtesRNBoa6P5)
render_from_model_view: deployed (fu-IgdgjYZp0WrSpTptYOWqSX)
tag_regions:            NOT deployed (NotFoundError)
segment:                deployed (fu-uD56yRHrmeEHejBPbQOj3z)
apply_material:         deployed (fu-MqqKx8ZFTXDnQApB9qveY7)
```

`tag_regions` was added to `spike/modal_app.py` in T14 (commit `2bca1d8`) but
T14 explicitly did NOT deploy ("Don't deploy.") and the overnight agent is
forbidden from running `modal deploy`. So the function exists in source but
the running app on Modal predates T14 and has no `tag_regions` symbol.

### Blocker 2: `modal.Function.lookup` is gone in modal 1.4.x

The driver script `spike/test_vlm_tagging.py` (T16) uses:

```python
fn = modal.Function.lookup("arch-rendering-spike", "tag_regions")
```

In modal 1.4.2 (the version in `spike/.venv`) `Function.lookup` no longer
exists — it was renamed to `Function.from_name(...).hydrate()`:

```
AttributeError: type object 'Function' has no attribute 'lookup'
```

`dir(modal.Function)` confirms `from_name` is now the public API.

So even if the function were deployed, the script as written would fail at
the lookup line. This is a pre-existing bug in T16's code.
