# copilot-agent — research + stress-test (2026-07-03)

**Headline:** By mid-2026 every major creative/CAD tool has converged on the same copilot shape — chat-native agent that calls real tools on real scene state, human retains final aesthetic authority, and every action is transaction-wrapped for undo — which maps almost exactly onto our tool's existing structured scene graph (semantic elements, material layers, entourage instances, sun/sky, camera, splat env).

## Key facts

- Autodesk Assistant went GA in Forma March 2026 as a multi-agent project-data supervisor, not a design-generation agent (autodesk.com/blogs/construction, 2026-03-25)
- Forma's Building Layout Explorer (neural CAD) generates floor-plan variants from massing but is explicitly marketed as requiring human verification, not one-click (adsknews.autodesk.com, 2026-06-02)
- Figma's AI agent reached broader GA rollout starting May 20, 2026: on-canvas prompt box (Cmd/Ctrl+Enter) + persistent chat sidebar, works on real components/tokens/variables, supports parallel exploration threads and saved /commands (figma.com/solutions/ai-design-agent; help.figma.com)
- Adobe Firefly AI Assistant public beta expanded into Photoshop, Premiere, Illustrator, InDesign, Frame.io sidebars on 2026-06-18; framed explicitly as an orchestration layer over existing app APIs, with the human retaining final aesthetic decisions (blog.adobe.com, venturebeat.com)
- NVIDIA's Chat USD (kit-usd-agents, Omniverse PB 26h1) uses a supervisor-routed multi-agent architecture over the USD scene graph with specialized code-gen/asset-search/scene-info nodes (github.com/NVIDIA-Omniverse/kit-usd-agents)
- Meta's IWSDK ships an MCP-over-WebSocket bridge from Claude Code into a running Vite/Three.js web app exposing scene-hierarchy and transform inspection tools, closing a perceive-act-verify dev loop — direct architectural precedent for bridging an agent into our R3F app (developers.meta.com/horizon)
- Unreal's Sage MCP wraps every agent tool call in a native FScopedTransaction joining the editor's real undo stack; multi-step actions collapse to one labeled undo entry; failures auto-rollback via Cancel(); state stays 'dirty' until explicit user save (github.com/alemdarlabs/sage-unreal-mcp/docs/engineering/transactions.md)
- PhotoFlow's Director-Reviewer-Reflector pipeline (visionary-laboratory.github.io/PhotoFlow) is a ready-made design for both auto-camera-framing and scene-critique copilot features
- Cutscene Agent (huggingface.co/papers/2604.25318) validates a two-stage camera pattern: fast parameterized shot-template placement, then optional vision-driven iterative refinement only when needed
- Verified Claude Agent SDK cost: 5-step tool-use task ~$0.0085 (Haiku 4.5) / $0.0255 (Sonnet 4.6) / $0.0425 (Opus 4.7) uncached; caching cuts 60-80%; SDK overhead is only ~42ms/tool-step vs raw API loop (claudeguide.io, 2026-05-10)
- Agent-loop cost scales closer to O(n^2) than O(n) because full context re-sends every turn; parallel tool calls fix latency (sum→max) but not cost (tianpan.co, 2026-04-20; learnaivisually.com)
- Unity Muse was sunset in 2024/2025 and replaced by 'Unity AI'; Sentis is an unrelated runtime ONNX inference engine — not a useful copilot precedent
- Editor/Manager surface separation (tight buffer-cursor UI vs. scannable multi-agent monitoring UI) independently converged across Google Antigravity, Cursor 3, GitHub Copilot, and Claude Code by mid-2026 (agentpatterns.ai, 2026-07-03)

## Recommendation

Build the copilot as a thin MCP-style bridge (Claude Agent SDK session <-> WebSocket <-> in-browser tool executor, following the IWSDK pattern) over our existing typed scene graph, not as a new generation surface. Every mutating tool call must be transaction-wrapped (Sage/Toffoli pattern) so it lands as one undoable, re-editable layer, consistent with the project's non-destructive core value. Ship in this order: (1) read-only scene critique/composition feedback first (zero mutation risk, cheapest to validate UX), (2) compound macros that call our existing material/entourage/sun APIs, (3) auto-camera-framing using a template-first + optional visual-refinement loop, (4) multi-view consistency guardian reusing our masked region_edit infra to directly attack the known hard problem. Surface the copilot as a docked chat affordance near the viewport plus a separate lightweight action-log panel (Editor/Manager split), not one overloaded chat panel. Enforce prompt caching and parallel tool-call batching from day one given verified quadratic cost growth in naive agent loops, and gate any hero-render-triggering macro behind an explicit cost confirmation consistent with the project's $0.05/session discipline.

## Open questions

- Which Claude model tier is right per action class (e.g., Haiku for scene-graph reads/critique, Sonnet for compound macro planning) — needs empirical latency/cost testing against our actual tool schema size once built, not just the generic benchmarks cited here
- Exact undo-stack integration mechanism for our React/R3F app (we have no native 'editor undo stack' like Unreal's UTransactor) — likely needs a custom command-pattern history akin to the Three.js builder-ux skill pattern found (bbeierle12/skill-mcp-claude), should be scoped as its own implementation task
- Whether Figma's 'save as reusable /command' pattern is worth building in v1 or is a v2 differentiator once usage patterns are observed
- No AEC-specific precedent exists yet for a chat-driven agent directly manipulating a live 3D viewport scene graph (Forma/TestFit/Hypar are all parametric-solver UX, not conversational) — this is unverified white space, worth validating with a small number of target architect users before over-investing
- Did not verify Autodesk's 'neural CAD' foundation model technical architecture in depth (out of scope for copilot-interaction dimension) — flagging in case another research dimension needs it

## Full report

## Precedent landscape (verified 2026)

**AEC-specific:** Autodesk Assistant (GA in Forma, March 2026) is a multi-agent "project-level" supervisor that routes to specialist agents over connected project data (RFIs, specs, issues) — closer to a PM copilot than a design copilot. Forma's Building Layout Explorer (neural CAD, generative floor-plan variants from massing) is Autodesk's actual design-generation agent, explicitly framed as "not one-click" — human verifies every output against local code (autodesk.com/blogs/construction, adsknews.autodesk.com, archbim.cloud, 2026-03/04/06). TestFit and Hypar are *not* conversational agents — they're parametric/constraint solvers with sliders (testfit.io, archpulse.co); useful as a pattern ("adjust any parameter, regenerate instantly, save as a scheme") but not as a copilot-interaction reference. Verdict: no AEC tool has yet shipped a true chat-driven scene-editing agent over a live 3D viewport — this is white space for us.

**Design tools (best interaction precedent):** Figma's agent (GA rollout from May 20, 2026) is the clearest model — lives in a persistent chat sidebar *and* an on-canvas prompt box (Cmd/Ctrl+Enter on a selected layer), works on real components/tokens/variables not placeholders, supports parallel threads to explore directions simultaneously, and lets teams package a successful workflow into a reusable `/command` skill (figma.com/solutions/ai-design-agent, help.figma.com, 2026). Adobe's Firefly AI Assistant (public beta since April 2026, expanded to Photoshop/Premiere/Illustrator/InDesign/Frame.io sidebars June 18 2026) is the clearest philosophy precedent: agent as **orchestration layer** over existing pro-grade tool APIs, human explicitly retains "the calls that only they can" — final aesthetic/creative decisions (blog.adobe.com, venturebeat.com, 2026-06-18). Both converge on: chat sidebar as primary surface, agent calls the app's own real tools/APIs (not a separate generation model bolted on), multi-step orchestration visible as a running log, human approves/refines rather than one-shots.

**Engine/DCC tool-calling architecture:** NVIDIA's Chat USD (kit-usd-agents, Omniverse PB 26h1) is a supervisor-routed multi-agent system over USD scene graph with specialized nodes (code-gen, asset search, scene-info) — direct architectural analog for routing intents to specialist tool-sets over our scene state (github.com/NVIDIA-Omniverse/kit-usd-agents, docs.omniverse.nvidia.com). The Blender MCP ecosystem exploded in 2026 (blender-copilot, blend-ai, BlenderCopilot, mcp-blender-agent — 4+ competing implementations, 100-300+ tools each) validates the "expose scene graph as typed tool-calls over a socket, let Claude/any MCP client drive it" pattern at a mature, battle-tested level — visual feedback loop (`analyze_scene` returns screenshot + structured metadata) is now table stakes.

**Closest exact architectural match to us:** Meta's IWSDK AI tooling (developers.meta.com, immersive-web-sdk) — Claude Code connects via MCP-over-stdio to a Vite dev server, which bridges via WebSocket to an in-browser MCP client that exposes Three.js scene-graph inspection (`get_scene_hierarchy`, `get_object_transform`) plus console/screenshot capture, closing a perceive-act-verify loop entirely in a web app dev environment. This is essentially our target architecture already validated in production: web3d-prototype's R3F/three scene *is* the same shape (semantic entity tree + transforms + material assignments), so an MCP bridge from a Claude Agent SDK session into our running Vite app, exposing scene-graph read/write tools, is a proven pattern, not a novel bet.

**Camera-framing / scene-critique agents (directly reusable designs):**
- **PhotoFlow** (visionary-laboratory.github.io/PhotoFlow) — closed-loop **Director → Reviewer → Reflector** pipeline: Director proposes candidate camera states from a "photographic blueprint," Reviewer scores rendered previews via rule checks + visual critique + pairwise comparison, Reflector turns failures into spatial memory (dead-zone suppression) to avoid repeating bad framings. This is a ready-made blueprint for "auto-camera framing" and "scene critique" capabilities.
- **Cutscene Agent** (huggingface.co/papers/2604.25318) — hierarchical subagents (cinematography, lighting, staging) + a **perceive-reason-act visual refinement loop**: template-based camera placement first (fast, parameterized "over-the-shoulder from A to B" intent), then a vision-capable subagent iteratively captures screenshots and nudges the camera until composition criteria are met. Two-stage (template → visual refinement) is the efficient pattern to copy rather than doing full closed-loop search from scratch every time.
- Magnific's "3D Scenes" and Intangible's "Compose mode" both hard-separate a **real spatial camera (position/lens/aspect/aim-target passed as structured parameters)** from the generative render call — validates our existing architecture (real R3F camera state feeding FLUX/ControlNet) over prompt-described framing.

**Undo/guardrails (this is the load-bearing finding for "non-destructive"):** The Unreal Engine "Sage" MCP pattern (github.com/alemdarlabs/sage-unreal-mcp, docs/engineering/transactions.md) is the single best reference: every agent tool call wraps in a transaction that joins the *native* undo stack, so a human Ctrl+Z reverses AI edits exactly like manual edits; multi-step agent actions collapse into **one** labeled undo entry ("Sage: Setup boss arena") rather than seven; failures trigger automatic rollback (`Cancel()`); modifications leave state "dirty," never auto-save, so the user has final write authority; optimistic-lock version conflicts are surfaced explicitly rather than silently overwritten. The broader "compensating-action" pattern (agentpatternscatalog/patterns) generalizes this: every forward action registers a paired inverse; on failure, compensators run in reverse order. Toffoli (theo-ai-lab/toffoli) adds a useful refinement: classify each action **reversible / compensable / irreversible** up front (deterministic rules first, LLM judge only for the ambiguous residual) and hard-block auto-execution of the irreversible class without human sign-off. For us: every agent action must resolve to (a) a new material/entourage/sun layer that's trivially removable, or (b) a flagged "irreversible" class (e.g., baking a hero render, which costs money) requiring explicit confirmation.

**Interaction-pattern convergence, mid-2026:** Independent convergence across Google Antigravity, Cursor 3, GitHub Copilot, and Claude Code on an **Editor/Manager surface split** (agentpatterns.ai, 2026-07-03) — a tight buffer-cursor "Editor View" for inline single-agent edits, separate from a scannable "Manager Surface" for monitoring/dispatching multiple parallel agent tasks. For us this maps to: a lightweight always-visible chat/command affordance docked to the 3D viewport (Editor-equivalent, tight to current selection/camera) plus a separate light-weight task/history panel showing completed and in-flight agent actions as an audit log (Manager-equivalent) — not one overloaded chat panel trying to do both.

**Cost/latency of agentic loops (verified, load-bearing for our $0.05/session cap discipline):** Agent-loop cost is **not** linear in tool calls — context re-sent every turn makes it effectively O(n²) in naive implementations; real teams report 5–30x cost overruns vs back-of-envelope estimates (tianpan.co, 2026-04-20; aicost.ai). Concrete Claude Agent SDK numbers (claudeguide.io, 2026-05-10, verified current): a 5-step tool-use task costs ~$0.0085 (Haiku 4.5), ~$0.0255 (Sonnet 4.6), ~$0.0425 (Opus 4.7) uncached; **prompt caching cuts this 60-80%** at steady traffic (cached Sonnet 4.6 5-step: $0.0072). Agent SDK adds only ~42ms/tool-step overhead vs a raw API loop — negligible. Parallel tool calls are a pure **latency** lever (collapses `sum(latencies)`→`max(latencies)`), not a cost lever — cost is identical regardless of dispatch order. Practical implication: a copilot action that fires 3-5 independent scene-graph reads (get materials, get sun state, get camera, list entourage) should be parallelized in one turn, and system-prompt/tool-schema caching is mandatory once the copilot ships broadly, or per-action cost will silently balloon.

**Unity Muse/Sentis status (verify claim):** Muse was **sunset in 2024/2025** and replaced by "Unity AI" (built into Editor, includes an AI Gateway + MCP server + asset generators) — not a copilot precedent worth building toward; Sentis is a runtime ONNX inference engine, unrelated to our copilot use case. Deprioritize this reference.

## 5–8 highest-value copilot capabilities for our tool (ranked)

1. **Ambient scene critique on demand** ("what's off here?") — vision-capable subagent screenshots the current viewport + reads scene-graph state (sun angle, material list, entourage density), returns a structured critique (composition, material coherence, lighting time-of-day mismatch) — PhotoFlow's Reviewer pattern, cheap (1-2 model calls, no scene mutation, zero undo risk). **Ship first** — lowest risk, clearest value, no guardrail complexity.

2. **Compound "do it for me" macros over existing structured actions** ("make it golden hour and add street trees along the front setback") — the agent decomposes into calls against our *existing* typed tools (sun-position setter, entourage-placement API, material-swap API) rather than freeform generation. Each sub-action is its own undoable layer per the Sage/compensating-action pattern; the whole macro collapses to one labeled undo entry.

3. **Auto-camera-framing** for hero-render composition — template-first (parameterized shot intents: "three-quarter approach," "street-level eye-height," "golden-hour western elevation") then optional visual-refinement loop (Cutscene Agent's two-stage pattern) only when the user asks for iteration, to control cost — camera is our real R3F camera (matches Magnific/Intangible's structured-camera-parameter approach), not a prompt description.

4. **Region-aware material recommendation** ("what would look good on this wall") — grounded in our actual 29-swatch PBR library + region semantic tag (already exists from Gemini tagging spike) rather than open-ended generation; returns 2-3 ranked swatch suggestions the architect clicks to apply (keeps direct-manipulation locus of control, matches Figma's "generate using real components, not placeholders" principle).

5. **Multi-view consistency guardian** — given our known hard problem (per-view FLUX drift), an agent role that runs *after* a hero render batch, diffs materials/geometry across views using the same vision-critique loop, and flags/re-triggers masked region_edit re-rolls only on the drifted regions — directly reuses our existing per-region masked re-roll infrastructure, turns a known pain point into a differentiated agent capability.

6. **Reusable workflow skills** ("save this as a preset") — Figma's `/commands` pattern: once an architect runs a successful macro (e.g., "autumn dusk street scene"), let them name and save it as a one-click reusable action scoped to their project's material/entourage library.

7. **Entourage scatter-and-critique** — agent proposes tree/bush/people placement respecting existing scatter-paint infra, then self-critiques density/occlusion via viewport screenshot before committing — same perceive-act loop, medium value since scatter-paint UX is already direct-manipulation and fast.

8. **Cost/session-budget-aware suggestion gating** — given our $0.05/session discipline as a house value, surface the copilot's own action costs before committing to any hero-render-triggering macro (batch renders are the expensive, semi-irreversible class per Toffoli's taxonomy) — a small but on-brand UX differentiator vs. competitors who hide agent cost entirely.

## Architecture recommendation
Claude Agent SDK session (not Managed Agents — we want local process control given Modal cost gating) with a custom MCP-style tool set exposing our scene graph (material assignments, entourage instances, sun/sky state, camera, splat env) as typed read/write tools, following the IWSDK bridge pattern (Vite dev server ↔ WebSocket ↔ in-browser tool executor) we already have proven infra to build on (three r0.184, R3F). Every mutating tool wraps in a compensating-action pair per Sage/Toffoli so `Ctrl+Z` and an explicit undo-layer stack both work. Split UI into a docked chat/command affordance near the viewport (Editor-surface) and a separate lightweight action-log panel (Manager-surface) rather than one panel. Cache system prompt + tool schemas aggressively; batch independent scene reads into parallel tool calls in the same turn.

## Adversarial stress-test (Opus 4.8)

**Verdict:** viable-with-changes

**Fatal flaws:**

- none

**Risks:**

- PRECEDENT MISREAD — the 'closest exact architectural match' is dev-tooling, not a product copilot. Meta's IWSDK bridge (the researcher's proof that a Claude-SDK↔WebSocket↔in-browser-tool loop 'is a proven pattern, not a novel bet') is explicitly AI-ASSISTED DEVELOPMENT TOOLING: Claude Code connects over stdio to a Vite DEV server driving a HEADLESS PLAYWRIGHT browser, at develop-time, for the DEVELOPER (verified: developers.meta.com/horizon iwsdk-ai-assisted-dev-tooling, iwsdk.dev/ai). Nobody has shipped this bridge to an END USER's live production tab. The target architecture (Agent SDK session serving a firm's architect in their own browser, with auth, multi-tenant session state, WebSocket reconnection under real network conditions, and Modal cost-gating in the loop) is a genuine net-new build, not a validated one. Downgrade all 'proven pattern' language to 'proven at dev-time only.'
- RELIABILITY OF MUTATION IS THE REAL COST — the researcher cites Figma and Autodesk as validation but omits their measured failure rates. His own class of source rates the Figma agent at 42% success on full-page generation, 68-74% on complex layouts, and — worse — documents the agent CLAIMING it finished tasks it hadn't and silently editing things it wasn't told to (dev.to 2-week test; medium.com/design-bootcamp; mantlr.com). Autodesk Assistant is explicitly Tech Preview with 'no commitments or warranties,' and its actual design-gen (Building Layout Explorer) is marketed 'not one-click, human verifies every output.' A mutation copilot that is wrong 1-in-4 times and occasionally lies about what it did is a net time-SINK for a professional under deadline — they'll audit every edit, which is slower than direct manipulation the tool already has. This is survivable ONLY because the researcher's OWN ranked ordering front-loads the zero-mutation capabilities (scene critique, material recommendation) — but capabilities #2/#5/#7 (compound macros, consistency guardian, entourage scatter) inherit this reliability tax and must be gated behind mandatory diff-preview + explicit-apply, never auto-commit.
- NO NATIVE UNDO STACK TO JOIN — the load-bearing 'non-destructive' guarantee leans on the Sage/Unreal FScopedTransaction pattern, but that pattern works because Unreal has a NATIVE editor transaction/undo stack the agent tool joins. This R3F web app has a per-feature localStorage layer stack and (per STATE.md) NO global command/undo bus. 'Every mutating tool wraps in a compensating-action pair so Ctrl+Z works' is therefore not a wiring job over existing infra — it requires first BUILDING a global transactional command bus across material layers, entourage instances, sun/sky, and camera, then making every existing direct-manipulation UI action route through it too (or agent-undo and manual-undo diverge). That's real foundational work the researcher's 'thin bridge' framing hides.
- COST DISCIPLINE vs VISION-LOOP CAPABILITIES — the researcher's own verified O(n²)-ish agent-loop cost finding collides with his highest-value capabilities. Scene critique (#1), auto-camera-framing (#3), and the consistency guardian (#5) all require VISION calls (screenshot the viewport, reason, iterate). A Cutscene-Agent-style refinement loop can be 5-15 vision turns; at Opus/Sonnet image-input rates with full-context re-send, an unbounded 'iterate until composition is good' loop can silently blow past the $0.05/session house cap that the whole project is disciplined around. Caching helps text/tool-schema tokens, not fresh screenshot tokens each turn. The consistency guardian (#5) is the worst case — it must diff MANY hero views (each an image) against each other. Must hard-cap iteration count and screenshot resolution per action, not just 'gate hero-render macros.'
- INCUMBENTS ARE ALREADY HERE, ON THE INSIDE — the researcher's 'no AEC tool has shipped a chat-driven scene-editing agent, this is white space' is already stale at the ship date. Verified 2026: D5 Render 3.0 ships '15+ AI features' incl. AI PBR Material Snap, SmartPlanting context-aware vegetation, AI Atmosphere Match; Enscape/Chaos Veras+Envision now ship an in-scene natural-language AI Assistant (beta) with light-mood-match, material/asset suggest, and one-click Smart Selection for material targeting — inside Revit/Rhino/SketchUp where the architect ALREADY works. The exact capabilities the researcher ranks #1/#3/#4 (critique, framing help, material recommendation) are being commoditized by incumbents who own the host and the render engine. The copilot is not a moat; it's table stakes racing to zero. The defensible wedge is the geometry-locked hero + splat-editable-environment, NOT the chat agent.
- WORKFLOW-REALITY PARTIAL MISS — the 'move the window 2ft after renders are done' test actually FAVORS this project's core (real 3D geometry → editing the window and re-firing the geometry-locked hero is genuinely non-destructive, which archviz studios CANNOT do — verified: late-stage change 'resets work completed in earlier stages,' requires 'substantial remodeling, retexturing, resetting camera and lighting,' eosvisions.com/rmdesignstudio). BUT this strength lives in the ENGINE + hero-render dimensions, not the copilot. A copilot that says 'sure, moving the window' and then fires N hero re-rolls across all saved views is exactly the semi-irreversible, cost-bearing, drift-prone action the multi-view-consistency problem is UNSOLVED for (full-360 chained turntable still loses the building on back views per STATE.md). So the single most valuable real-firm scenario is one the copilot cannot yet safely automate end-to-end — it can only tee up the human.

**Recommendations:**

- Reframe the headline from 'proven pattern' to 'dev-time-proven, product-runtime-novel.' Keep the build order but be honest that a production Agent-SDK↔browser bridge with auth/session/reconnect is net-new engineering, and scope it as such rather than 'thin bridge over existing infra.'
- Ship ONLY the read-only, zero-mutation capabilities first and treat them as the actual product bet: scene critique (#1) and grounded material recommendation over the real 29-swatch library (#4). These have no undo-stack dependency, no O(n²) mutation cost, and dodge the incumbent race because they're grounded in THIS tool's semantic scene graph. Validate that architects find them useful before writing a single mutating tool.
- Before ANY mutating capability (#2/#5/#7), build the missing foundation: a global transactional command bus that BOTH the direct-manipulation UI and the agent route through. Without it the Sage/non-destructive promise is vaporware. This is a prerequisite, not a day-2 nicety — surface it as its own workstream.
- Make every mutating agent action DIFF-PREVIEW-THEN-APPLY, never auto-commit, given the verified 42-74% reliability and the 'agent lies about completion' failure mode. The architect approves a visible before/after per action. This preserves direct-manipulation locus of control and turns the reliability tax into a review step instead of a silent-corruption risk.
- Hard-cap vision-loop iterations and screenshot resolution per action, and put a running $-spent meter on the copilot itself (the researcher's #8, but promote it to non-negotiable). The $0.05 cap must be enforced in the loop, not just at hero-render trigger — a runaway critique/refinement loop is the real budget threat.
- Abandon 'copilot is white-space' positioning; D5 3.0 and Enscape/Veras already ship in-scene AI material/vegetation/atmosphere assistants inside the host apps. Position the copilot as a thin accelerant over the DEFENSIBLE core (geometry-locked hero + editable-splat environment + non-destructive real-3D late edits), and seriously weight the project's own stated parallel track — integrating AI assistance INTO Enscape/V-Ray/D5 — because the incumbents own the host and the render engine and are moving fast on exactly these features.
- Do NOT let the copilot auto-drive the multi-view hero re-roll (the highest-value real-firm scenario) until multi-view consistency is solved — full-360 chained turntable still loses the building on unseen sides. Scope the copilot here to TEEING UP the human (flag drift, propose the region_edit, let the architect fire it), consistent with 'architects direct-manipulate, don't prompt.'
