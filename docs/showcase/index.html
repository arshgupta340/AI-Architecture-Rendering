AI Architecture Rendering · Project story

From "prompt a building" to the model is the product

Part 1

The journey, start to today

Gold dots are the turning points. Everything in between is the work that taught us why we had to turn.

FEB 2026
Killed the first idea: "type a building, then click it" Pivot 1
Generating a building from text and then trying to identify its parts meant two guessing steps stacked on top of each other. We anchored to a real 3D model instead.
MAR–APR 2026
Settled the inputs & the plumbing
Use a shaded screenshot of the architect's 3D model as input; use a vision-AI to tag regions (wall, window, mullion…) so "click a wall" resolves to a real area.
MAY 2026
Renderer bake-off + overnight scaffolding
Rather than bet on one AI renderer, we compared eight on the same input and scored them. Stood up the wiki as the single source of truth so no session loses context.
12 JUN 2026
Stopped guessing from pixels — took the truth from the model Pivot 2
The vision-AI kept missing thin window mullions. But the host software (Rhino) already knows every element exactly. We switched to reading ground truth straight from the model — and deleted two whole AI stages.
13 JUN 2026
Left 2D image-editing behind for real 3D Pivot 3
Keeping a building looking identical from different angles is a permanent uphill fight in 2D. In real 3D it's free — so we rebuilt the product as a live web 3D tool.
14–15 JUN 2026
Built the "decked-out" render stack
Materials, sun, entourage, three quality tiers, a photoreal "hero" render (live on GPU), and a Gaussian-splat environment backdrop — all in the browser.
3 JUL 2026
Grand idea → focused, defensible product Latest turn
A 17-agent research fleet stress-tested the big vision (AI video, editable splat worlds, a copilot). The honest verdict shaped a shippable plan: the mesh is the product.
Part 2

How we decided to pivot

Every turn followed the same rule: cheapest information first, and let measured evidence — not opinion — force the change. Here's each one in plain language.

Pivot 1 · the compounding-error trap

Stop generating buildings from scratch

February 2026 · DECISIONS → dropped-text-to-image
Before
Type a prompt → AI invents a building → user clicks parts in that image to identify them.
→
After
Start from the architect's real 3D model screenshot → AI only has to re-skin the geometry it's given.
Why: two AI guessing-steps in a row compounded errors — the model invented geometry that the next step then couldn't reliably identify. Architects already have a 3D model, so anchoring to it removes a whole class of failure.
In plain terms: don't ask the AI to imagine the building and then re-read its own imagination. Give it the real thing and let it do one job.
Pivot 2 · pay for data you already own?

Take the ground truth from the model, not from pixels

12 June 2026 · DECISIONS → plugin-first-pivot  ·  host-integration research
Before
Show the render to a vision-AI and hope it labels every wall, window, and mullion correctly.
→
After
Ask Rhino directly — it hands over exact per-element IDs and true depth for free.
Why: measured, the vision-AI scored ~0.4 accuracy and found zero mullions on a mullion-grid façade. Meanwhile the host software knows every element precisely. We were paying an accuracy tax on data we could just ask for.
In plain terms: why squint at a photo of a spreadsheet when you can open the spreadsheet?
Pivot 3 · consistency should be free

Move from 2D image-editing to real-time 3D

13 June 2026 · DECISIONS → web3d-pivot  ·  competitor teardown
Before
Edit a flat 2D render with AI — and fight to keep the building identical across every camera angle.
→
After
Load the real geometry into a live 3D engine in the browser — angles, swaps, and sun are exact by construction.
Why: multi-view consistency was the 2D pipeline's deepest wound. In real 3D it disappears: the geometry is the same object from every angle. We already had clean geometry + element IDs from Pivot 2 — so the hard part was already solved.
In plain terms: instead of hand-drawing the same building five times and hoping they match, build it once and walk around it.

Part 4

The latest turn: stress-testing the grand idea

The big vision was: AI-generated entourage → cinematic video fly-throughs → an editable Gaussian-splat world → an embedded AI copilot → and integration with Enscape / V-Ray / Lumion. We sent a fleet of 17 AI agents to research and attack every piece.

The unanimous finding: every pillar is a real tech demo, but only one is a defensible product. The mesh is the product — everything generated has to be a re-derivable render of the mesh, never the thing you edit.
Model-locked re-rendering
Real element IDs → geometry-locked photoreal render, re-editable per region. ~90% already built.
Ship now
"Fly-through" as a still turntable
6–12 locked hero angles you click through — 80% of the wow, none of the drift.
Ship, changed
Splat backdrop
Static, honestly labeled "illustrative — not survey." Real 3D stays in the mesh.
Ship, changed
AI video fly-through
Every model warps the building across camera motion; geometry-true video has no hosted API yet.
Defer
Editable splat world
Research-stage; splats bake lighting & fail on glass/thin members — i.e. most of architecture.
Kill as a pillar
Mutating copilot (v1)
AI edit-agents are wrong ~1-in-4, and there's no undo bus yet for them to plug into.
Read-only first

The one competitor fact that settled it: Chaos now bundles Veras (running the same class of image model our hero uses) free into every Enscape / V-Ray tier — used by 85 of the top 100 firms. There is no model-layer moat. The only durable edge is geometry-truth from the actual model that survives the industry's #1 pain: "move the window 2 ft" arriving after the renders are done.

Part 5

Where it goes next

Ship the one defensible thing first; let the first 100 users tell us which of the shiny extras they'd actually pay for. Each extra sits behind an evidence gate.

Phase 0 · this month

The core, productized

  • Global command / undo bus — makes "non-destructive" actually true
  • One-button Rhino capture plugin
  • Auth + GPU cost-gating on the hero render
  • Project file that persists every edit as a layer
Wow: "that wall, in travertine" → re-render → "move the window" → everything re-propagates.
Phase 1 · this quarter

Multi-angle without the drift

  • Still turntable (6–12 locked angles)
  • Labeled static splat backdrop
  • Light-coherent entourage
  • Read-only copilot (scene critique)
Wow: a click-through turntable of a locked photoreal building seated in real site context.
Phase 2 · gated

Prove the premium — or don't

  • Concept-clip video (only if geometry-true & margin-safe)
  • "Remove that object" splat edit
  • Copilot macros (preview-then-apply)
  • Second host: Revit or SketchUp
Each ships only when live evidence clears its gate (PRD §6).
